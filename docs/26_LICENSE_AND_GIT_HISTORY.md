## Release-scope decision (operator, 2026-11-13)
**Everything releasable is to be released under a permissive licence: code, content, implementations, infrastructure, analysis records and weights.** Consequences (binding for planning):
1. **Weights we train from scratch on our own synthetic data** (G1 readers, fixed-latent memories, future compressors on SODH-type tasks) are fully ours → Apache-2.0, releasable once training data/config hashes and the run record are published with them.
2. **pi0/pi0.5 and anything derived from them (fine-tunes, conversions, distilled students) cannot be released under Apache/MIT** (Gemma terms flow down, `docs/20 (withheld from the public release)`): excluded as a backbone for released weights; stays NO-GO.
3. **SmolVLA**: licences are Apache-2.0 at code/weights/VLM level, but the training-data lineage is unresolved (SmolVLM2 data reportedly includes CC BY-NC items; community LeRobot data licences unenumerated, `docs/30 (withheld from the public release)`). A released fine-tune of `smolvla_base` is therefore **blocked until a data-licence audit closes**. Planning default: release only *our* modules (context/memory encoder, adapters, expert trained from scratch) and let users fetch the base backbone themselves; any redistribution of base-derived weights requires the audit.
4. Octo (MIT, OXE per-dataset licences unread) and RDT-1B (MIT claim, 50 pretraining datasets unlicensed, RH20T partly NC reported) need the same audit before any derived-weight release.
5. Real data we do not own (RoboMME, LeRobot samples) is never redistributed; released artefacts reference upstream revisions and hashes only. Weights trained on such data inherit the data's terms and need the audit too.
6. Docs 16/20/22/30 stay withheld until their third-party claims are verified against primary texts; the release-scope decision raises the priority of that verification (SmolLM2/T5/SigLIP cards, Cauldron/LLaVA-Video/ShareGPT4Video terms, OXE and LeRobot community dataset licences).
7. Weights release checklist (per artefact): training data licences enumerated · base-model lineage and terms · config/data/seed hashes · run record with real git SHA · model card with limitations · Apache-2.0 `NOTICE` entries · human sign-off.
